## 2. ประสิทธิภาพ

| รายการ | เป้า (p95, เครือข่ายสำนักงาน) |
|---|---|
| API อ่านรายการ/รายละเอียด | ≤ 300 ms |
| API action (submit, decision) | ≤ 800 ms (งานหนักย้ายไป worker) |
| ทะเบียนเอกสาร 5,000 แถว (แบ่งหน้า + กรอง + ค้นหา) | ≤ 500 ms |
| เปิด PDF หน้าแรก (ไฟล์ 20 MB) บนเว็บ | ≤ 3 วินาที |
| สร้างใบนำส่ง PDF + ส่งอีเมล | ≤ 60 วินาทีหลังกดส่ง |
| Pull sync มือถือ (เปลี่ยนแปลง ≤ 500 รายการ) | ≤ 5 วินาทีบน 4G |
| เวลาเปิดแอปมือถือ (cold start) | ≤ 3 วินาที บนเครื่องระดับกลาง |

แนวทาง: index ตาม `03-data-model.md`, หลีกเลี่ยง N+1 (ใช้ `include`/`select` ที่ชัดเจน), จำกัด `pageSize ≤ 100`, ไฟล์ไม่วิ่งผ่าน API

## 3. ความพร้อมใช้งานและการกู้คืน

| รายการ | เป้า |
|---|---|
| Availability | 99.5% ในเวลาทำการ (จ.–ส. 07:00–20:00) |
| RPO | ≤ 15 นาที (PostgreSQL WAL archiving ด้วย pgBackRest หรือ managed PITR) |
| RTO | ≤ 4 ชั่วโมง |
| Backup DB | full รายวัน, เก็บ 30 วัน + รายเดือน 12 เดือน, เข้ารหัส, เก็บนอกเครื่อง |
| Backup ไฟล์ | bucket versioning + replicate ไปอีกที่ (อีก region/อีกเครื่อง) |
| ทดสอบกู้คืน | ทุกไตรมาส บันทึกผลใน runbook |
| Deploy | zero-downtime ไม่บังคับ; ช่วงบำรุงรักษานอกเวลาทำการ แจ้งผ่าน `/app/config.maintenanceMessage` |

## 4. การติดตามระบบ (Observability)

- Log JSON (pino) มี `requestId`, `userId`, `route`, `durationMs`; เก็บ 90 วัน
- Sentry: API, worker, web, mobile (release = git sha / app version)
- Health: `/health/live`, `/health/ready` (DB, Redis, S3 ต้อง up; Gotenberg แสดงสถานะแต่ไม่ทำให้ ready ล้ม เพราะสร้าง PDF ใน worker)
- ตัวชี้วัดที่ต้องดู: latency p95, error rate 5xx, ความยาวคิว BullMQ, outbox ค้าง > 5 นาที, พื้นที่ดิสก์/บัคเก็ต, การ login ล้มเหลวผิดปกติ
- แจ้งเตือนผู้ดูแล (อีเมล/LINE ภายหลัง) เมื่อ: ready check ล้ม 3 ครั้งติด, outbox ค้าง > 10 นาที, backup ล้ม

## 5. ภาษา วันที่ และภูมิภาค

- UI ภาษาไทยเป็นค่าเริ่มต้น สลับอังกฤษได้; ทุกข้อความอยู่ในไฟล์แปล (web: next-intl, mobile: ARB/gen-l10n) — ห้าม hard-code ข้อความในโค้ด
- ป้าย enum มาจาก `docs/data/enum-labels.json` (สร้างไฟล์แปลด้วยสคริปต์ ไม่คัดลอกมือ)
- วันที่แสดงแบบ พ.ศ. ตามค่าเริ่มต้น (`Intl.DateTimeFormat('th-TH')` ใช้ปฏิทินพุทธโดยอัตโนมัติ; ถ้าผู้ใช้เลือก ค.ศ. ใช้ `th-TH-u-ca-gregory`)
- เขตเวลาธุรกิจ `Asia/Bangkok` สำหรับวันครบกำหนด งานตามเวลา และวันที่ในรายงาน
- เรียงข้อความภาษาไทยด้วย `Intl.Collator('th')` (web) / `collation` ใน query เมื่อจำเป็น
- PDF ใช้ฟอนต์ Sarabun ฝังในไฟล์

## 7. การเข้าถึง (Accessibility)

- WCAG 2.1 AA พื้นฐาน: contrast ≥ 4.5:1, ใช้งานด้วยคีย์บอร์ดได้ทุกฟอร์ม, label ครบ, focus ชัดเจน
- ปุ่มบนมือถือ ≥ 48×48 dp; ฟอร์มหน้างานใช้งานด้วยมือเดียวได้; ฟอนต์ปรับตามการตั้งค่าเครื่อง

## 8. คุณภาพโค้ดและการดูแลรักษา

- TypeScript `strict`, ESLint + Prettier; Dart `flutter analyze` ไม่มี warning; `very_good_analysis` หรือ `flutter_lints`
- Test coverage ขั้นต่ำ: domain logic ฝั่ง API 90%, service 70%; มือถือ sync engine 90% (ดู `11-testing.md`)
- ทุก PR ผ่าน CI (`02-architecture.md` §9) และอัปเดตสเปก/ADR เมื่อพฤติกรรมเปลี่ยน
- ไม่มีโค้ดที่ใช้ภายนอกแบบต้องซื้อ license โดยไม่ได้รับอนุมัติ (ตรวจ license ของ dependency ใหม่ทุกตัว: MIT/BSD/Apache-2.0/ISC/OFL ใช้ได้)
