# 07 · Web UI (Next.js)

## 1. หลักการ

- **Desktop-first** สำหรับงานสำนักงาน/แล็บ (≥ 1280 px) ใช้บนแท็บเล็ตแนวนอนได้; ตารางข้อมูลแน่นแต่อ่านง่าย
- **ภาษาไทยเป็นหลัก** ทุกข้อความผ่าน next-intl; ป้าย enum มาจาก `docs/data/enum-labels.json` (สร้างไฟล์แปลด้วย `node tools/gen-i18n-enums.mjs`)
- **Server ตัดสินทุกอย่าง** — แสดงปุ่มตาม `allowedActions`, ปุ่ม disabled พร้อมเหตุผลตาม `blockedActions`; ไม่เขียนกติกาธุรกิจซ้ำใน UI
- ทุกการกระทำที่ย้อนกลับไม่ได้ (ส่ง, อนุมัติ, void, ยกเลิก) มี dialog ยืนยัน; action ที่ต้องมีเหตุผลบังคับกรอก
- บอกสถานะให้เห็นทันที: badge สีตามสถานะ, วันครบกำหนดเป็นสีแดงเมื่อเลยกำหนด, ความเห็นค้างเป็นตัวเลข

## 3. Design system และ component กลาง

- shadcn/ui + Tailwind CSS; ฟอนต์ UI **Noto Sans Thai** (OFL) ผ่าน `next/font`; ตัวเลขในตารางใช้ `font-variant-numeric: tabular-nums`
- สีสถานะ (semantic token → ใช้กับทุก enum ผ่าน map ใน `src/lib/status-colors.ts`):

| Token | ใช้กับ (ตัวอย่าง) |
|---|---|
| `neutral` | DRAFT, PENDING, NOT_STARTED |
| `info` | IN_REVIEW, ACTIVE, IN_PROGRESS, SENT, SUBMITTED |
| `success` | APPROVED, ISSUED, ACKNOWLEDGED, PASS, CLOSED (issue) |
| `warning` | APPROVED_WITH_COMMENTS, ON_HOLD, RESPONDED, ใกล้ครบกำหนด |
| `danger` | REJECTED, VOID, CANCELLED, FAIL, เลยกำหนด, CODE_3, CODE_4 |
| `muted` + ขีดฆ่า | SUPERSEDED |

| Component | หน้าที่ | กติกา |
|---|---|---|
| `DataTable` | ตารางจาก TanStack Table | pagination/sort/filter ที่ server; sync กับ URL query; จำคอลัมน์ที่ซ่อนต่อผู้ใช้ (localStorage); เลือกหลายแถว + bulk action; ปุ่มส่งออก Excel |
| `FilterBar` | ตัวกรองเหนือตาราง | chip แสดงตัวกรองที่ใช้, ล้างทั้งหมด |
| `StatusBadge` | แสดงสถานะ enum | ป้ายจากไฟล์แปล + สีจาก map |
| `UserPicker` | เลือกคน | จาก `/users/directory` + กรองตามสิทธิ์/บทบาทที่ server ส่ง (เช่น eligible reviewers) |
| `DateField` | เลือกวันที่ | แสดง พ.ศ./ค.ศ. ตามค่าผู้ใช้ ส่งค่า `YYYY-MM-DD` |
| `FileUploader` | อัปโหลด | presigned PUT, progress, ยกเลิก/ลองใหม่, แสดง PROCESSING → AVAILABLE/REJECTED (ผ่าน SSE `file.processed`) |
| `PdfViewer` | ดู PDF | pdfjs-dist, thumbnail หน้า, zoom/fit, layer หมุด/กรอบความเห็น (พิกัด normalize), โหมด "เพิ่มความเห็น" |
| `SignatureDialog` | ลงนาม | เลือก รหัสผ่าน/PIN, แสดงสิ่งที่กำลังลงนาม (เอกสาร Rev. การตัดสิน) และเลขใบอนุญาตที่ใช้ |
| `ReasonDialog` | ยืนยันพร้อมเหตุผล | ใช้กับ void/cancel/reject/reassign |
| `ProblemAlert` | แสดง error | แสดง `detail` จาก problem+json + `requestId` (คัดลอกได้) |
| `ConflictDialog` | 409 `CONFLICT_STALE_VERSION` | แสดงว่ามีผู้อื่นแก้ → โหลดใหม่ (ฟอร์มเก็บค่าที่ผู้ใช้พิมพ์ไว้ให้เทียบ) |
| `EmptyState` | ไม่มีข้อมูล | บอกว่าทำอะไรต่อได้ (เช่น ปุ่มลงทะเบียนเอกสาร) |

## 4. การดึงข้อมูล ฟอร์ม และ auth

- API client: `openapi-fetch` จาก `packages/api-contract` (ใส่ `X-CSRF-Token`, `Accept-Language`, `X-Request-Id` อัตโนมัติ)
- TanStack Query key: `[resource, params]` เช่น `['documents', projectId, filters]`; SSE event → `invalidateQueries` ตาม `04-api-conventions.md` §10
- ฟอร์ม: react-hook-form + zod; error จาก server (`errors[].field`) map ลงฟิลด์
- auth: `proxy.ts` (Next.js 16 ขึ้นไป) ตรวจว่ามี cookie session ถ้าไม่มี redirect `/login?next=`; ข้อมูลผู้ใช้/สิทธิ์จาก `GET /auth/me` เก็บใน context
- route สาธารณะ: `/login`, `/t/[token]` (หน้าดาวน์โหลดใบนำส่ง)

## 6. หน้าจอ MVP

### 6.1 งานของฉัน (`/`)

- การ์ด: "รอฉันตรวจ" (จำนวน + 5 รายการใกล้ครบกำหนด), "ความเห็นที่ฉันต้องตอบ", "เอกสารของฉันที่ถูกตีกลับ", "ผลตอบกลับลูกค้าที่ต้องแก้ (CODE_3/4)", "แจ้งเตือนล่าสุด"
- ทุกรายการคลิกไปหน้าที่เกี่ยวข้องโดยตรง

### 6.4 ส่งตรวจ (dialog จากปุ่ม "ส่งตรวจ")

- แม่แบบ workflow (ค่าเริ่มต้นจากประเภทเอกสาร; เปลี่ยนได้ถ้ามีสิทธิ์)
- แต่ละขั้น: ชื่อขั้น, ชนิด, `UserPicker` ที่แสดงเฉพาะผู้มีสิทธิ์ (`/revisions/{id}/eligible-reviewers`) พร้อมป้ายใบอนุญาต (สาขา ระดับ วันหมดอายุ) และผู้ที่ถูกตัดสิทธิ์เพราะแยกหน้าที่แสดงเป็นสีเทาพร้อมเหตุผล
- ตัวอย่างวันครบกำหนดของขั้นแรก, หมายเหตุถึงผู้ตรวจ
- ตรวจ `blockedActions` ก่อนเปิด (เช่น ยังไม่มี PDF)

### 6.6 ใบนำส่ง

- รายการ: เลข, หัวเรื่อง, ผู้รับ, วัตถุประสงค์, สถานะ, วันที่ส่ง, จำนวนรายการ, ผลตอบกลับ (สรุป)
- สร้าง/แก้ (DRAFT): ผู้รับ = ลูกค้าของโครงการ + ผู้ติดต่อที่ `receivesTransmittals` (เพิ่มอีเมลได้), วัตถุประสงค์, วิธีส่ง, ข้อความ; ตารางรายการ — ปุ่ม "เพิ่มเอกสาร" เปิดตัวเลือกที่แสดงเฉพาะ revision ที่ส่งได้ (BR-DOC-060) พร้อมคำเตือน BR-DOC-061; ขนาดไฟล์รวมและคำเตือนเปลี่ยนเป็นลิงก์ (BR-DOC-062); ปุ่ม "ดูตัวอย่างใบนำส่ง" (PDF)
- หลังส่ง: สถานะการส่งอีเมล, ลิงก์ (หมดอายุ/เพิกถอน/ขยาย), ประวัติดาวน์โหลด, ฟอร์มบันทึกการรับ (วันที่ + ไฟล์), บันทึกผลตอบกลับรายรายการ

### 6.7 ค่าออกแบบ (`/projects/[id]/design-basis`)

- หัว: ฉบับ (revNo) + สถานะ, อัตราการไหลเฉลี่ย (m³/วัน), peak factor, ปีเป้าหมาย, ประชากรเทียบเท่า, มาตรฐานเป้าหมาย
- ตาราง: พารามิเตอร์ (เลือกจาก Parameter หรือพิมพ์เอง), หน่วย, ค่าน้ำเข้า (ค่าเฉลี่ย/ต่ำสุด/สูงสุด), ค่าเป้าหมายน้ำทิ้ง (แสดงเกณฑ์มาตรฐานข้างๆ เพื่อเทียบ), ที่มา, หมายเหตุ
- ปุ่ม: บันทึก, อนุมัติ (ลงนาม), สร้างฉบับใหม่; แถบประวัติฉบับก่อนหน้า (เทียบค่าที่เปลี่ยน)

### 6.8 ผู้ดูแลระบบ

- ผู้ใช้: ตาราง + ฟอร์ม (ข้อมูล, บทบาทหลายค่า, แผนก, ใบอนุญาต (ตาราง + อัปโหลดสำเนา + ปุ่มยืนยัน), รีเซ็ตรหัส, ปลดล็อก, เพิกถอน session)
- บทบาท: ตาราง matrix สิทธิ์ × บทบาท (checkbox) จัดกลุ่มตามโมดูล
- แม่แบบ workflow: รายการขั้น (ลากเรียง, stepOrder เดียวกัน = ขนาน), ชนิด, บทบาทที่อนุญาต, ลงนาม, ใบอนุญาต, วันครบกำหนด, optional
- เลขเอกสาร: แก้ pattern พร้อมตัวอย่างเลขถัดไป
- Audit: ตาราง + ตัวกรอง + ดู before/after แบบ diff

## 7. หน้าดาวน์โหลดสาธารณะ (`/t/[token]`)

หน้าเรียบ ไม่มีเมนูระบบ: โลโก้/ชื่อบริษัท, "ใบนำส่งเลขที่ …", วันที่ส่ง, วันหมดอายุ, ตารางเอกสาร (เลข ชื่อ Rev. ไฟล์) + ปุ่มดาวน์โหลด, ปุ่มดาวน์โหลดทั้งหมด (ZIP); หมดอายุ → ข้อความ "ลิงก์หมดอายุ กรุณาติดต่อ <อีเมลผู้ส่ง>"; มี `noindex`
