# M07 · เก็บตัวอย่างภาคสนาม (เฟส 3)

> Data model: `sampling.prisma` + `Sample`, `SampleContainer`, `CustodyTransfer` ใน `lab.prisma` · มือถือ: `08-mobile.md` §9

## 1. ขอบเขต

วางแผนทริป (เว็บ) → เตรียมขวดและฉลาก QR → เก็บตัวอย่างบนมือถือแบบออฟไลน์ (GPS รูป ค่าภาคสนาม สแกนขวด ลายมือชื่อตัวแทนลูกค้า) → ส่งมอบตัวอย่างให้แล็บ (chain of custody)

## 2. กติกาธุรกิจ

- **BR-SMP-001** ทริปมีหัวหน้าทีม 1 คนและสมาชิก; จุดแวะ (stop) เรียงลำดับ แต่ละจุดผูกกับจุดเก็บตัวอย่าง งานวิเคราะห์ และแพ็กเกจ/วิธี
- **BR-SMP-002** รายการขวดคำนวณจาก `containerType`, `containerVolumeMl`, `preservation` ของวิธีวิเคราะห์ในแต่ละจุด โดยรวมวิธีที่ใช้ขวด/สารกันเสียเดียวกันเป็นขวดเดียว (ถ้าปริมาตรรวมไม่เกินขนาดขวด)
- **BR-SMP-003** ฉลาก QR พิมพ์ล่วงหน้า (PDF ขนาดฉลาก 50×30 มม. หรือ A4 แบบตาราง) ข้อความ = `SampleContainer.label` รูปแบบ `C-` + 8 ตัวอักษร base32 สุ่ม ไม่ซ้ำ; ฉลากยังไม่ผูกตัวอย่างจนกว่าจะสแกนหน้างาน
- **BR-SMP-010** บันทึกจุดแวะ SAMPLED ต้องมี: เวลาเก็บ, พิกัด GPS, รูป ≥ 1, สแกนขวดครบตามรายการ (หรือระบุเหตุผลที่ขาด); พิกัดห่างจากจุดที่ลงทะเบียนเกิน 200 ม. → เตือนและต้องใส่หมายเหตุ
- **BR-SMP-011** ค่าภาคสนามต้องระบุเครื่องมือ; เครื่องมือเลยกำหนดสอบเทียบ → เตือน (ไม่บล็อกในภาคสนาม) และแสดงในรายงาน
- **BR-SMP-012** ข้ามจุด (SKIPPED) ต้องมีเหตุผล; ระบบแจ้งผู้ดูแลงานวิเคราะห์
- **BR-SMP-013** ตัวอย่างที่สร้างบนมือถือได้ `id` จาก client; `code` (S26-…) ออกเมื่อ sync; ความสัมพันธ์ขวด ↔ ตัวอย่างบันทึกตอนสแกน
- **BR-SMP-020** ส่งมอบให้แล็บ: สร้าง `CustodyTransfer` รวมหลายตัวอย่าง มีลายมือชื่อผู้ส่ง (บนมือถือ) และผู้รับ (บนมือถือหรือแท็บเล็ตแล็บ) → ตัวอย่างเข้าสู่ขั้นตอนรับตัวอย่างของ M06
- **BR-SMP-021** ทริป COMPLETED เมื่อทุกจุด SAMPLED/SKIPPED และตัวอย่างทุกตัวอยู่ใน CustodyTransfer แล้ว

## 3. API (ย่อ)

| Endpoint | สิทธิ์ |
|---|---|
| `GET/POST /sampling-trips`, `GET/PATCH /sampling-trips/{id}`, `POST /sampling-trips/{id}/start` · `/complete` · `/cancel` | `sampling.plan` / หัวหน้าทีม |
| `GET/POST/PATCH /sampling-trips/{id}/stops[/{stopId}]` | `sampling.plan` |
| `GET /sampling-trips/{id}/bottle-list` · `/labels.pdf` | `sampling.plan` |
| `POST /sampling-stops/{id}/arrive` · `/sampled` · `/skip` | `sampling.perform` (สมาชิกทริป) |
| `POST /sampling-stops/{id}/samples` (id จาก client), `POST /samples/{id}/containers` (สแกน), `POST /sampling-stops/{id}/field-measurements` | `sampling.perform` |
| `POST /custody-transfers` `{ id, sampleIds, relinquishSignatureFileId, … }`, `POST /custody-transfers/{id}/receive` | `sampling.perform` / `lab.sample.receive` |

ทริปที่ผู้ใช้เป็นสมาชิก sync ลงมือถือด้วย scope `trip:<tripId>` (รวมข้อมูลจุด วิธี แพ็กเกจ เครื่องมือ ที่ต้องใช้)

## 4. หน้าจอ

- เว็บ `/sampling/trips`: ปฏิทินทริป, ฟอร์มทริป (เลือกจุดจากแผนที่/รายการ, ลากเรียงลำดับ), รายการขวด, พิมพ์ฉลาก
- มือถือ: รายการทริปของฉัน → ทริป (แผนที่ + ลำดับจุด) → จุดแวะ (เช็กอิน GPS → รูป → ค่าภาคสนาม → สแกนขวด → ลายมือชื่อตัวแทนลูกค้า → เสร็จ) → ส่งมอบตัวอย่าง

## 5. สถานการณ์ทดสอบรับงาน

| รหัส | สถานการณ์ | ผลที่ต้องได้ |
|---|---|---|
| AT-SMP-01 | ทริป 3 จุด ไม่มีสัญญาณตลอดวัน กลับถึงสำนักงานแล้ว sync | ตัวอย่าง รูป ค่าภาคสนาม ลายมือชื่อ ขึ้นครบ ได้รหัสตัวอย่าง |
| AT-SMP-02 | สแกนขวดฉลากเดียวกันกับ 2 ตัวอย่าง | ครั้งที่ 2 ถูกปฏิเสธ `SMP_CONTAINER_ALREADY_LINKED` |
| AT-SMP-03 | บันทึกเก็บตัวอย่างห่างจุด 500 ม. | เตือนและบังคับหมายเหตุ |
