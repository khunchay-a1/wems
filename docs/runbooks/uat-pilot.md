## 4. เกณฑ์ผ่าน UAT

- สถานการณ์ U-01 ถึง U-20 ผ่านทั้งหมด หรือข้อที่ไม่ผ่านมีแผนแก้และไม่ใช่ความเสี่ยงหลัก 4 ข้อใน `06-security.md` §1 (ใช้แบบผิดฉบับ, อนุมัติโดยผู้ไม่มีสิทธิ์, ผลถูกแก้โดยไม่มีร่องรอย, ข้อมูลรั่วผ่านลิงก์)
- ไม่มี issue ระดับ "ร้ายแรง" ค้าง; ระดับ "สำคัญ" ≤ 3 ข้อพร้อมวันที่แก้
- ผ่าน checklist `security-checklist.md` §8 และทดสอบกู้คืนบน staging แล้ว (`backup-restore.md` §4)

ระดับ issue: ร้ายแรง = ข้อมูลผิด/สูญหาย/สิทธิ์รั่ว; สำคัญ = งานหลักทำไม่ได้แต่มีทางเลี่ยง; เล็กน้อย = หน้าตา/ข้อความ

## 5. Pilot (1–2 โครงการ, 4–6 สัปดาห์)

| เรื่อง | รายละเอียด |
|---|---|
| เลือกโครงการ | โครงการออกแบบที่เพิ่งเริ่ม มีเอกสาร 50–300 รายการ ทีม 5–10 คน และมีวิศวกรสนามอย่างน้อย 1 คน |
| ข้อมูลเดิม | นำเข้าทะเบียนด้วย Excel template (M04 §8); ไฟล์ revision ก่อนหน้าแนบเฉพาะฉบับใช้งาน |
| การทำงานคู่ขนาน | 2 สัปดาห์แรกเก็บทะเบียนเดิมคู่ไปด้วย แล้วเลิกใช้เมื่อทีมยืนยัน |
| อบรม | 1 ชั่วโมงต่อบทบาท (DC/วิศวกร/ผู้อนุมัติ/PM) + 30 นาทีสำหรับแอปมือถือ |
| ช่องทางแจ้งปัญหา | กลุ่มแชตของ pilot + แบบฟอร์ม (หน้าจอ, เวลา, ผู้ใช้, สิ่งที่คาด/ที่เกิด); ผู้ดูแลดู log ตาม `requestId` |
| ตัวชี้วัด | จำนวนเอกสาร/revision ที่ผ่านระบบ, เวลาเฉลี่ยส่งตรวจ→อนุมัติ, จำนวนใบนำส่ง, ปัญหาที่พบต่อสัปดาห์, ความพึงพอใจ (แบบสอบถาม 1–5) |
| ทบทวน | ทุกสัปดาห์ 30 นาที; สิ้นสุด pilot ตัดสิน go/no-go ใช้งานทั้งบริษัท |
| ถอยกลับ | ส่งออก MDL (Excel) และไฟล์ revision จากระบบได้ตลอด — ทีมกลับไปใช้ทะเบียนเดิมได้ทันที |
